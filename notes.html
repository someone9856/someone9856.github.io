1 Study of network commands (Linux & Windows)

Main manual – Practical 1 Run on PC

Aim

To study and practise the basic networking commands used in Linux and Windows.

Requirements

  • PC with Windows (Command Prompt) or Linux (Terminal)
  • Network connection

Theory

  • ping – tests reachability using ICMP Echo Request/Reply.
  • ipconfig /all (Windows) / ip address show (Linux) – shows IP, mask, gateway, DNS, DHCP, MAC.
  • arp -a – shows IP-to-MAC (ARP) table.
  • hostname – shows computer name.
  • netstat – active TCP/IP connections, ports, routing table (netstat -r).
  • nslookup – DNS lookup: gives IP of a domain name.
  • tracert (Win) / traceroute (Linux) – hops a packet takes. pathping = ping + tracert (Windows only).
  • nbtstat -a – NetBIOS name resolution problems.
  • route – show/modify IP routing table.
  • Linux only: ip (replaces ifconfig), mtr (ping+traceroute), tcpdump (packet capture), nmcli (set IP).

Procedure

  1. Open Command Prompt (Windows) or Terminal (Linux).
  2. Run each command one by one and note the output.
  3. Check ping results: 0% loss = good; 'Request timed out' = no reply; 'Destination host unreachable' = no route; 'Unknown host' = wrong name.

Output

sample output
Reply from 8.8.8.8: bytes=32 time=10ms TTL=117 … Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)

Result

Basic network commands were studied and executed successfully.

Viva questions

  • Which command checks reachability of a host? – ping
  • Which command shows hops to destination? – tracert / traceroute
  • Which command shows IP configuration? – ipconfig / ip address
  • Which command shows TCP port status? – netstat
  • Modify IP in Linux? – nmcli connection modify ... ipv4.addresses ... or ip address add

2 Study of network cables – make straight & cross cable

Main manual – Practical 2 Physical lab – no PC run

Aim

To study the types of network cables and to make a straight-through and a cross-over Ethernet cable.

Requirements

  • Cat5e/Cat6 UTP cable
  • 2 × RJ45 plugs
  • Crimping tool
  • LAN tester (optional)

Theory

  • Types: UTP, STP, Coaxial, Fibre optic.
  • UTP – cheap, easy, affected by EMI; Cat5 100 Mbps, Cat5e 1 Gbps. STP – shielded, Cat6/6a up to 10 Gbps, costly.
  • Coaxial (RG-6, RG-59, RG-11) – high bandwidth, immune to interference, bulky; used in TV / cable internet.
  • Fibre optic (single/multi mode) – very high speed, long distance, secure, expensive.
  • Straight cable: same wiring (A) on both ends – connects unlike devices (PC–switch, PC–router).
  • Cross cable: wiring A on one end, B on the other – connects like devices (PC–PC, switch–switch).
  • T568A order: G/W, G, O/W, Bl, Bl/W, O, Br/W, Br. T568B order: O/W, O, G/W, Bl, Bl/W, G, Br/W, Br. (Straight = same on both ends, Cross = A on one end, B on the other.)

Procedure

  1. Thread the plug shield onto the cable.
  2. Strip about 1.5 cm of outer jacket on both ends.
  3. Untangle the 4 twisted pairs and arrange colours in order A / B as required.
  4. Cut the wires evenly.
  5. Hold the plug with clip away from you, gold pins towards you, and push the wires fully in.
  6. Check the jacket goes inside the plug, then crimp with the tool.
  7. Repeat for the other end.
  8. Test with a LAN tester or by connecting two devices.

Result

Straight-through and cross-over cables were made and tested.

Viva questions

  • Difference between cross and straight cable? – wiring order on the two ends differs
  • Cable to connect two PCs? – cross cable
  • Cable to connect switch to PC? – straight cable
  • Category of cable used in your lab? – Cat5e / Cat6 (check)

  • Which layer does a switch work at? – Data link (Layer 2)

  5. File → Save the capture.

Packet list filtered to only the chosen protocol; details pane shows Frame → Ethernet → IP → TCP/UDP → application layers.

Packets were captured and filtered by TCP/UDP, ARP, DNS, HTTP, ICMP and DHCP; encapsulation was observed.

6 Hamming code – error detection & correction

Main manual – Practical 6 (manual gives aim only; code below is a tested sample) Run on PC

Aim

To write a program that implements Hamming code to detect and correct a single-bit error in transmitted data.

Requirements

  • Python 3 (or C / Java)
  • VS Code / IDLE / any editor

Theory

  • Hamming code adds redundant (parity) bits at positions 1, 2, 4, 8 … (powers of 2) to data bits.
  • Each parity bit checks the positions whose binary index contains that bit.
  • At the receiver the parity checks give a number (syndrome): 0 = no error, otherwise it is the position of the wrong bit – flip it to correct.
  • Number of redundant bits r: 2^r ≥ m + r + 1 (8 data bits → r = 4, codeword = 12 bits).
  • Detects 2-bit errors, corrects 1-bit errors.

Procedure

  1. Sender: read text, convert each character to 8-bit binary.
  2. Insert parity bits at positions 1, 2, 4, 8 using even parity.
  3. Save the codewords in the 'channel' file.
  4. Receiver: read channel file, recompute the parity checks.
  5. If syndrome ≠ 0 print error position and flip that bit.
  6. Remove parity bits, convert binary back to ASCII and print.

Program

hamming.py
# Hamming code (even parity): each ASCII char = 8 data bits -> 12-bit codeword
R = [1, 2, 4, 8]                      # parity bit positions (powers of 2)

def encode(byte):
    data = format(byte, "08b")
    code = [0] * 13                   # index 1..12 used
    j = 0
    for pos in range(1, 13):
        if pos not in R:
            code[pos] = int(data[j]); j += 1
    for p in R:                       # parity p covers positions having bit p set
        code[p] = sum(code[i] for i in range(1, 13) if i & p and i != p) % 2
    return "".join(map(str, code[1:]))

def decode(word):
    code = [0] + [int(b) for b in word]
    err = sum(p for p in R if sum(code[i] for i in range(1, 13) if i & p) % 2)
    if err:                           # syndrome = position of the wrong bit
        print("  error at position", err, "-> corrected")
        code[err] ^= 1
    return int("".join(str(code[i]) for i in range(1, 13) if i not in R), 2)

if __name__ == "__main__":
    text = input("Enter text: ")
    sent = [encode(ord(c)) for c in text]
    print("Sent    :", " ".join(sent))
    # SENDER writes to channel file; RECEIVER reads it back
    open("channel.txt", "w").write(" ".join(sent))
    recv = open("channel.txt").read().split()
    if input("Induce an error? (y/n): ").lower() == "y":
        w = list(recv[0]); w[4] = "1" if w[4] == "0" else "0"; recv[0] = "".join(w)
        print("Received:", " ".join(recv), "(bit 5 of 1st char flipped)")
    print("Decoded :", "".join(chr(decode(w)) for w in recv))

Output

sample output
Sent    : 000110011000 010111001001
Received: 000100011000 010111001001 (bit 5 of 1st char flipped)
  error at position 5 -> corrected
Decoded : Hi

Result

Hamming code was implemented; a single-bit error was detected, located and corrected.

Viva questions

  • Parity bit positions? – powers of 2 (1,2,4,8)
  • How many errors can Hamming correct? – 1 bit
  • What is the syndrome? – binary number giving error position

7 Sliding window protocol (flow control)

Main manual – Practical 7 (manual gives aim only; code below is a tested sample) Run on PC

Aim

To implement flow control at the data link layer using the sliding window protocol and simulate frame flow from sender to receiver.

Requirements

  • Python 3
  • Editor / Command Prompt

Theory

  • Sliding window lets the sender transmit several frames (window size W) before waiting for an acknowledgement.
  • Frames are numbered; the receiver sends ACK n (received correctly) or NACK n (error).
  • Go-Back-N: on error the sender resends from the damaged frame onwards.
  • Gives better channel utilisation than stop-and-wait.

Procedure

  1. Input window size and message (1 character per frame).
  2. Create frames [frame no, DATA].
  3. Send up to W frames; receiver checks the frame number and replies ACK/NACK.
  4. If ACK as expected, slide the window and send new frames; if NACK resend from that frame.
  5. Induce an error and observe retransmission.

Program

sliding_window.py
# Sliding window (Go-Back-N) simulation - 1 character per frame
msg = input("Enter message: ")
w = int(input("Enter window size: "))
bad = input("Frame number to damage once (blank = none): ")
bad = int(bad) if bad else -1

base = 0                              # oldest un-acknowledged frame
while base < len(msg):
    top = min(base + w, len(msg))
    print(f"\nSender window [{base}..{top - 1}]")
    expected = base
    for n in range(base, top):
        print(f"  Send  frame {n} : DATA='{msg[n]}'")
        if n == bad:                  # receiver gets a damaged frame
            bad = -1
            print(f"  Recv  frame {n} : ERROR -> NACK {n}")
            break
        print(f"  Recv  frame {n} : OK    -> ACK {n}")
        expected = n + 1
    if expected < top:
        print(f"  Go-Back-N: resend from frame {expected}")
    base = expected
print("\nAll frames delivered:", msg)

Output

sample output
Sender window [0..2]
  Send  frame 0 : DATA='H'
  Recv  frame 0 : OK    -> ACK 0
  Send  frame 1 : DATA='E'
  Recv  frame 1 : ERROR -> NACK 1
  Go-Back-N: resend from frame 1 …
All frames delivered: HELLO

Result

Sliding window protocol was simulated; frames were sent, acknowledged and retransmitted after an induced error.

Viva questions

  • What is window size? – frames sent without waiting for ACK
  • Go-Back-N vs Selective Repeat? – GBN resends from the error onward, SR only the lost frame
  • Which layer? – Data link

Program

ping.py
import subprocess
import platform

print("=" * 50)
print(" Customized Ping Utility")
print("=" * 50)
host = input("Enter Website or IP Address: ")
system = platform.system()
if system == "Windows":
    command = ["ping", "-n", "4", host]
else:
    command = ["ping", "-c", "4", host]
try:
    result = subprocess.run(command, capture_output=True, text=True)
    print("\nPing Results\n")
    print(result.stdout)
    if result.returncode == 0:
        print("Server Status : Reachable")
    else:
        print("Server Status : Unreachable")
except Exception as e:
    print("Error:", e)

H6 Anonymous FTP scanner (Python)

Separate handout – Expt 6 (not in main manual) Run on PC

Aim

To develop a Python anonymous FTP scanner using ftplib and check whether an FTP server allows anonymous login.

Requirements

  • Windows/Linux PC
  • Python 3 (ftplib is built in)
  • An FTP server you are authorised to test

Theory

  • FTP (port 21) transfers files; some servers allow login with user 'anonymous' and any e-mail as password.
  • The scanner connects, tries anonymous login, and lists the directory if successful.
  • Use only on servers you own or are permitted to test.

Procedure

  1. Import FTP and all_errors from ftplib.
  2. Connect to host:21 with timeout.
  3. Try login('anonymous', 'anonymous@example.com').
  4. If it works, list files with nlst(); else print the error.
  5. Close the connection.

Program

ftp_scanner.py
from ftplib import FTP
from ftplib import all_errors

def anonymous_ftp_scan(host, port=21):
    print("=" * 50)
    print(" ANONYMOUS FTP SCANNER")
    print("=" * 50)
    print(f"Target: {host}")
    print(f"Port  : {port}")
    print()
    ftp = FTP()
    try:
        print("[1] Connecting to FTP server...")
        ftp.connect(host, port, timeout=10)
        print("[+] FTP server is reachable")
        print("[+] Server response:", ftp.getwelcome())
        print("\n[2] Testing anonymous login...")
        ftp.login(user="anonymous", passwd="anonymous@example.com")
        print("[+] Anonymous login SUCCESSFUL")
        print("[!] The FTP server permits anonymous access.")
        print("\n[3] Checking accessible directory...")
        files = ftp.nlst()
        if files:
            print("[+] Directory listing is available:")
            for item in files:
                print("   ", item)
        else:
            print("[-] Directory is empty or listing is unavailable.")
        ftp.quit()
    except all_errors as error:
        print("[-] Anonymous login failed or FTP connection failed.")

            pass

H7 Simple calculator using XML-RPC

Separate handout – Expt 7 (not in main manual) Run on PC

Aim

To design, implement and verify a remote calculator using XML-RPC in Python (client–server).

Requirements

  • Python 3
  • Two Command Prompt windows

Theory

  • RPC lets a client call a function that runs on a remote server as if it were local.
  • XML-RPC encodes the call as XML and sends it over HTTP.
  • Server registers functions; client uses ServerProxy to call them.

Procedure

  1. Server: import SimpleXMLRPCServer, define add/subtract/multiply/divide (divide checks zero).
  2. Create server on localhost:8000, register functions, serve_forever().
  3. Client: connect with xmlrpc.client.ServerProxy('http://localhost:8000/').
  4. Read two numbers, call remote methods, print results.

Program

calciserver.py
from xmlrpc.server import SimpleXMLRPCServer

def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

def multiply(a, b):
    return a * b

def divide(a, b):
    if b == 0:
        return "Division by zero not allowed"
    return a / b

server = SimpleXMLRPCServer(("localhost", 8000))
print("XML-RPC Calculator Server Running on Port 8000...")
server.register_function(add, "add")
server.register_function(subtract, "subtract")
server.register_function(multiply, "multiply")
server.register_function(divide, "divide")
server.serve_forever()

Program

calciclient.py
import xmlrpc.client

proxy = xmlrpc.client.ServerProxy("http://localhost:8000/")
a = float(input("Enter First Number: "))
b = float(input("Enter Second Number: "))
print("\nAddition       =", proxy.add(a, b))
print("Subtraction    =", proxy.subtract(a, b))
print("Multiplication =", proxy.multiply(a, b))
print("Division       =", proxy.divide(a, b))

H8 Reverse TCP connection using Python sockets

Separate handout – Expt 8 (not in main manual) Run on PC

Aim

To implement a TCP socket based reverse-connection demo with a listener and a connector on localhost.

Requirements

  • Python 3
  • Two Command Prompt windows

Theory

  • In a normal connection the client connects to a server. In a reverse connection the connector initiates the connection to the waiting listener.
  • TCP socket flow: socket → bind → listen → accept (listener); socket → connect (connector); send/recv; close.
  • This demo only exchanges messages on 127.0.0.1:5000 – no remote command execution.

Procedure

  1. Listener: create TCP socket, bind 127.0.0.1:5000, listen(1), accept.
  2. Receive the message, send a reply, close.
  3. Connector: create TCP socket, connect to 127.0.0.1:5000.
  4. Send message, receive reply, print, close.

Program

listener.py
import socket

HOST = "127.0.0.1"
PORT = 5000

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind((HOST, PORT))
server.listen(1)
print("Waiting for reverse connection...")
conn, addr = server.accept()
print("Connected from:", addr)
message = conn.recv(1024).decode()
print("Received:", message)
conn.send("Hello from listener".encode())
conn.close()
server.close()

Program

connector.py
import socket

HOST = "127.0.0.1"
PORT = 5000

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
print("Connecting to listener...")
client.connect((HOST, PORT))
client.send("Hello from reverse connector".encode())
reply = client.recv(1024).decode()
print("Listener replied:", reply)
client.close()

Output

sample output
Listener: Waiting for reverse connection...
Connected from: ('127.0.0.1', 54781)
Received: Hello from reverse connector
Connector: Listener replied: Hello from listener

Result

Connector initiated a TCP connection to the listener on localhost and messages were exchanged.

Viva questions

  • Socket type for TCP? – SOCK_STREAM
  • What does listen() do? – waits for incoming connections
  • Port used? – 5000
