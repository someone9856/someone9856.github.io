1 Study of network commands (Linux & Windows)

Main manual – Practical 1 Run on PC

  1. Open Command Prompt: press Win+R, type cmd, Enter.
  2. Check connectivity
    commands
    ping 8.8.8.8
ping www.google.com
  3. IP configuration
    commands
    ipconfig /all
hostname
  4. ARP and connections
    commands
    arp -a
netstat
netstat -r
  5. DNS and path
    commands
    nslookup www.google.com
tracert www.google.com
pathping www.google.com
  6. Take a screenshot / copy the output of each command for your record.

Expected output

output
Reply from 8.8.8.8: bytes=32 time=10ms TTL=117 … Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)

3 Packet Tracer environment & hub vs switch

Main manual – Practical 3 Cisco Packet Tracer

  1. Open Packet Tracer.
  2. End Devices → drag 4 PCs. Network Devices → Hubs → drag 1 hub.
  3. Connections → Copper Straight-Through → connect each PC (FastEthernet0) to the hub.
  4. Repeat with 4 more PCs and a 2960 switch.
  5. Click PC → Desktop → IP Configuration → set IP e.g. 192.168.1.1 … 192.168.1.4, mask 255.255.255.0.
  6. Click 'Add Simple PDU' (closed envelope icon), click source PC then destination PC.
  7. Switch to Simulation mode → press Play/Capture and watch: hub sends to all PCs, switch only to the target.

Expected output

output
Hub: PDU copied to every port. Switch: first time floods (ARP), then only the destination port.

4 Set up a LAN using a switch and Ethernet cables

Main manual – Practical 4 + Handout 'Ex. 4 LAN Setup' (clearer) Cisco Packet Tracer

  1. Open Packet Tracer. End Devices → add 4 PCs. Switches → add a 2960 switch.
  2. Connections → Copper Straight-Through: connect each PC FastEthernet0 → switch Fa0/1 … Fa0/4 (green lights = link up).
  3. For each PC: Desktop → IP Configuration → Static → IP 10.1.1.1 / .2 / .3 / .4, mask 255.0.0.0.
  4. Switch IP (optional): click switch → CLI
    commands
    enable
configure terminal
interface vlan 1
ip address 10.1.1.5 255.0.0.0
no shutdown
exit
  5. Ping test: PC → Desktop → Command Prompt
    commands
    ping 10.1.1.2
ping 10.1.1.3
ping 10.1.1.4
  6. Data sharing: add a Server-PT, IP 10.1.1.10 / 255.0.0.0, Services → HTTP ON. From a PC: Desktop → Web Browser → http://10.1.1.10 (page loads).
  7. Simulation mode: send a ping and watch the switch forward by MAC address.

Expected output

output
Reply from 10.1.1.2: bytes=32 time<1ms TTL=128  (4 sent, 4 received, 0% loss)

5 Packet capture with Wireshark

Main manual – Practical 5 Run on PC

  1. Install Wireshark from wireshark.org (also install Npcap when asked).
  2. Open Wireshark, double-click your active interface (Wi-Fi or Ethernet).
  3. Generate traffic: open a website and run ping google.com in cmd.
  4. Click the red Stop button.
  5. Type one filter at a time in the filter bar and press Enter
    commands
    tcp
arp
dns
http
icmp
bootp
  6. Click a packet and expand Ethernet / IP / TCP in the Details pane (this shows encapsulation).
  7. Statistics → Flow Graph (for tcp / dns filter).
  8. File → Save As → name the capture, e.g. lab5.pcapng.

Expected output

output
Packet list filtered to only the chosen protocol; details pane shows Frame → Ethernet → IP → TCP/UDP → application layers.

7 Sliding window protocol (flow control)

Main manual – Practical 7 (manual gives aim only; code below is a tested sample) Run on PC

  1. Save as sliding_window.py.
  2. Run
    commands
    python sliding_window.py
  3. Enter message e.g. HELLO, window size 3, damaged frame number 1.
  4. Observe: NACK for frame 1, then Go-Back-N resend and the window sliding.

Expected output

output
Sender window [0..2]
  Send  frame 0 : DATA='H'
  Recv  frame 0 : OK    -> ACK 0
  Send  frame 1 : DATA='E'
  Recv  frame 1 : ERROR -> NACK 1
  Go-Back-N: resend from frame 1 …
All frames delivered: HELLO

8(a) Nmap – discover live hosts (ARP, ICMP, TCP/UDP)

Main manual – Practical 8(a) Online (TryHackMe)

  1. Create/login to a TryHackMe account and open tryhackme.com/room/nmap01.
  2. Click Start AttackBox (browser terminal).
  3. Run in the AttackBox terminal (replace MACHINE_IP)
    commands
    nmap -sn MACHINE_IP/24             # ping scan (host discovery)
nmap -PR -sn MACHINE_IP/24        # ARP scan
nmap -PE -sn MACHINE_IP/24        # ICMP echo scan
nmap -PP -sn MACHINE_IP/24        # ICMP timestamp
nmap -PM -sn MACHINE_IP/24        # ICMP address mask
nmap -PS80,443 -sn MACHINE_IP/24  # TCP SYN ping
nmap -PU -sn MACHINE_IP/24        # UDP ping
  4. Answer the room's questions (they are checked online).
  5. Scan only the room's target machine – nothing else.

Expected output

output
Nmap scan report for 10.10.x.x  Host is up (0.0010s latency).
Nmap done: 256 IP addresses (N hosts up)

8(b) Wireless LAN configuration in Packet Tracer

Main manual – Practical 8(b) Cisco Packet Tracer

  1. Add a Wireless Router (Linksys) and 3 PCs. If a PC has only Ethernet: power off → swap the Ethernet module for a wireless module → power on.
  2. Click router → GUI → Wireless tab: SSID MotherNetwork → Save.
  3. Wireless Security tab: WEP, key 0123456789 → Save.
  4. Router IP is 192.168.0.1. Set PCs static: PC0 192.168.0.2, PC1 192.168.0.3, PC2 192.168.0.4, mask 255.255.255.0, gateway 192.168.0.1.
  5. PC → Desktop → PC Wireless → Connect → Refresh → MotherNetwork → Connect → key 0123456789.
  6. Test: PC0 → Command Prompt
    commands
    ping 192.168.0.3
ping 192.168.0.1

Expected output

output
Wireless device connected to MotherNetwork (CH 6, signal 100%, WEP). Ping replies from 192.168.0.x.

9 Subnetting in Packet Tracer

Main manual – Practical 9 Cisco Packet Tracer

  1. Add 1 router, 2 switches and 4 PCs; cable with straight-through (router–switch, switch–PC).
  2. Plan: subnet A 192.168.1.0/27 (gateway .1, PCs .11-.12), subnet B 192.168.2.0/27 (gateway .1, PCs .11-.12), mask 255.255.255.224.
  3. Router CLI
    commands
    enable
configure terminal
interface GigabitEthernet0/0
ip address 192.168.1.1 255.255.255.224
no shutdown
exit
interface GigabitEthernet0/1
ip address 192.168.2.1 255.255.255.224
no shutdown
end
write memory
  4. Each PC: IP from its subnet, mask 255.255.255.224, gateway = router IP of that subnet.
  5. Test from a PC in subnet A
    commands
    ping 192.168.1.1
ping 192.168.2.11
  6. To show 'without router': remove the router link – cross-subnet ping fails.

Expected output

output
Within subnet: replies. Across subnets via router: replies (first packet may time out due to ARP). Without router: Request timed out.

10(a) Internetworking with a router (2 networks)

Main manual – Practical 10(a) Cisco Packet Tracer

  1. Packet Tracer: add 1 router and 2 PCs; connect PC0 → router Fa0/0, PC1 → router Fa0/1 (copper cable).
  2. Router CLI
    commands
    enable
config t
interface FastEthernet0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
interface FastEthernet0/1
ip address 192.168.20.1 255.255.255.0
no shutdown
  3. PC0 → IP Configuration: 192.168.10.2, 255.255.255.0, gateway 192.168.10.1.
  4. PC1 → IP Configuration: 192.168.20.2, 255.255.255.0, gateway 192.168.20.1.
  5. PC0 Command Prompt
    commands
    ping 192.168.20.2
  6. Or use Add Simple PDU PC0 → PC1 and check 'Successful' in the event list.

Expected output

output
Reply from 192.168.20.2: bytes=32 time<1ms TTL=127

10(b) Wireless router + DHCP server + Internet cloud

Main manual – Practical 10(b) Cisco Packet Tracer

  1. Add: PC, Laptop, Wireless Router, Cable Modem, Cloud, Server (rename it Cisco.com).
  2. Cabling: PC–router (copper straight, Ethernet1), router Internet–modem Port1 (copper straight), modem Port0–cloud (coaxial), cloud–server (copper straight).
  3. Wireless router → GUI → Wireless: SSID HomeNetwork; Setup: DHCP Enabled, Static DNS 1 = 208.67.220.220 → Save.
  4. Laptop: power off, replace copper module with WPC300N, power on; Desktop → PC Wireless → Connect to HomeNetwork.
  5. PC: Desktop → IP Configuration → DHCP.
  6. Cloud: Physical tab add missing modules; Config → Cable: Coaxial ↔ Ethernet → Add; Ethernet interface → Provider Cable.
  7. Server (Cisco.com): IP 208.67.220.220, mask 255.255.255.0 (from the addressing table; the manual text ends before this step).
  8. PC Command Prompt
    commands
    ipconfig /all
ping 208.67.220.220
  9. Open Web Browser on the PC and open the server IP to confirm.

Expected output

output
PC gets 192.168.0.x by DHCP; ping to 208.67.220.220 replies.

H9 Topology with one router, two switches and PCs

Separate handout – Expt 9 (similar to manual 10(a) but not the same heading) Cisco Packet Tracer

  1. Add 4 PCs, 2 switches (2960), 1 router (4331 or 2911).
  2. Connect: PC0–SW0 Fa0/1, PC1–SW0 Fa0/2, PC2–SW1 Fa0/1, PC3–SW1 Fa0/2, SW0 Gi0/1–Router Gi0/0/0, SW1 Gi0/1–Router Gi0/0/1.
  3. PCs: PC0 192.168.10.10, PC1 192.168.10.11 (gw 192.168.10.1); PC2 192.168.20.10, PC3 192.168.20.11 (gw 192.168.20.1); mask 255.255.255.0.
  4. Router CLI (type no if asked about initial configuration)
    commands
    enable
configure terminal
interface GigabitEthernet0/0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit
interface GigabitEthernet0/0/1
ip address 192.168.20.1 255.255.255.0
no shutdown
end
write memory
  5. PC0 → Command Prompt
    commands
    ping 192.168.10.1
ping 192.168.20.10

Expected output

output
Request timed out (first packet, ARP) then Reply from 192.168.20.10: bytes=32 time<1ms TTL=127
